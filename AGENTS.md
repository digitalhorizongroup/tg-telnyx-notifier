# TG Telnyx Notifier

## Комментарии и докстринги

Правило общее для всех файлов, а не для языка: `#`, `//`, `--`, `<!-- -->` и
докстринги любого уровня — модуля, класса, метода, функции.

Комментарий и докстринг описывают код таким, какой он **сейчас**. Это отметка
«здесь читатель споткнётся», а не запись в журнал. Как к текущему виду пришли —
дело `git log -p` и переписки; в файл попадает вывод, а не путь к нему.

Ни прошедшего времени, ни будущего:

| Если в тексте | То пишется не уточнение, а |
| --- | --- |
| «раньше было», «убрали», «вернули», «стало» | diff — его показывает `git log -p` |
| «замерено», «проверено», «сравнили» | протокол проверки вместо свойства кода |
| «решили», «выбор был», «по просьбе» | обсуждение вместо свойства кода |
| «пока так», «потом переделаем», «пока не реализовано» | TODO без адресата и срока |
| даты, номера задач и сессий | ссылка на историю вместо факта о коде |

Второй признак лога — длина: уточнение занимает одну-две строки, три — предел.
Абзац на десяток строк пересказывает, как строку писали, а не что о ней нужно
знать, когда её читают.

Лог:

```python
# Сначала слали через общий клиент, но он держал одно соединение на процесс и
# на второй отправке ловил таймаут. Пробовали пул на 4 — не помогло, замерено
# на нагрузке 20 rps. В итоге вернулись к клиенту на вызов.
client = TelnyxClient()
```

То же решение как свойство строки — почему код такой и что сломается, если
сделать иначе:

```python
# Клиент на вызов, не общий: он держит одно соединение на процесс и на
# параллельной отправке отдаёт таймаут вместо очереди.
client = TelnyxClient()
```

Отдельно про докстринг: он отвечает на то, чего **нет** в коде, — инварианты,
единицы измерения, смысл `None`, предусловия, побочные эффекты. Предложение,
которое выводится из имени, сигнатуры или аннотаций, не пишется. Перечня
функций, истории правок и TODO в докстринге нет.

Закомментированного кода в дереве нет — для этого есть git.
